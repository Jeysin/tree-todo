## 2. 树形（脑图）视图

> v0.4 起：画布与全部脑图交互由 Mind Elixir 提供；React Flow / d3-hierarchy 已移除。节点上只额外叠加待办 checkbox 与 pending/done 视觉。


### 2.1 布局

- **方向**：从左到右的水平树（根在左、子节点向右生长），符合「任务分解」的心智模型；单根。
- **实现（决策 D4）**：使用 Mind Elixir（fork/本地补丁）作为脑图交互底座，负责布局、展开/收起、拖拽、折叠角标、平移缩放、键盘导航与原地编辑；前端只在其节点上叠加待办 checkbox 与状态视觉。
- **重算时机**：完全交给 Mind Elixir 的布局与拖拽机制；不再维护 React Flow 式的节点坐标。
- **尺寸**：节点宽度按内容自适应（有上限 min/max），文字完整折行、不省略，节点高度随折行行数增长；父子连线锚点在节点左右两侧中点。

### 2.2 节点视觉状态

| 状态 | 样式 |
|---|---|
| pending | 空心圆圈 checkbox + 正常文字 |
| done | 实心对勾 + 文字划线 + 整体降透明度；其下连线整条变灰（传达「这条支线已走完」） |
| 选中 / 焦点 | 描边高亮；焦点节点响应键盘操作 |
| 编辑中 | 节点就地变为 Mind Elixir 的内联输入层（`contenteditable`），提交后恢复卡片 |

### 2.3 画布交互

| 操作 | 交互 |
|---|---|
| 缩放 | 按 Mind Elixir 原生方式：触控板双指捏合 / 缩放控件；范围 10%–400% |
| 平移 | 按 Mind Elixir 原生方式：按住 Space + 拖拽画布 / 鼠标拖拽空白 / 触控板双指拖动 |
| 适应视图 | Shift+1 与状态栏按钮：缩放至整树可见 |
| 定位 | 点击平铺视图条目跳转定位（见 §3.3） |
| 视口记忆 | 每个文档独立保存平移与缩放（按文档 id 持久化）：新建 / 首次打开默认 100% + 根节点居中；切换文档、从平铺 / 统计 / 回收站返回、重启应用后恢复该文档上次视口。只有用户操作（拖拽 / 缩放 / 定位）会改变视口，任何文档操作都不复用其他文档的视口 |

### 2.4 折叠 / 展开

- 完全使用 Mind Elixir 的原生折叠角标与展开/收起交互（点击角标、方向键、`Ctrl+.` / `Ctrl+,`）。
- 折叠状态持久化在 `nodes.collapsed`（见 `02-data-model.md` §1.3）。
- **不**在角标上叠加节点数量；保持 Mind Elixir 的 `+ / −` 角标视觉。

### 2.5 性能策略

- Mind Elixir 负责渲染与布局；只渲染未折叠路径上的节点（折叠是第一优化手段）。
- 目标：可见节点 ≤ 2000 时保持交互流畅；5000 节点树（折叠后可见 ≤ 500）无感知延迟。集成前需用真实数据做性能冒烟。

### 2.6 隐藏已完成（v0.5）

- 顶栏「展开全部」右侧的小眼睛按钮（悬停提示「隐藏已完成节点」），开启后只渲染未完成节点：done 节点及其整棵子树（父 done ⇒ 子孙必 done）从脑图中移除。
- 根任务始终保留：全部完成时画布上只剩根，作为「这条线走完了」的锚点。
- 开关状态**按文档记忆**（`tree-todo.hideDone.{docId}`）：切换文档、重启应用后各自保持。
- 已完成节点不参与签名；开启隐藏时把 status 纳入结构签名，状态翻转后立即重建脑图。
- 从平铺视图点击某个已完成条目时，若该文档开着隐藏，则自动关闭开关再定位（并 toast 说明），避免「点了没反应」。

## 3. 平铺视图

### 3.1 定位

树形视图看**结构**，平铺视图看**存量**：把所有叶子节点拉平，集中显示「还有哪些事没做」「做完了哪些」。

### 3.2 设计

- 数据来源：**前端基于内存快照计算**（全量树启动时经 `get_tree` 加载一次，叶子 = 无子节点的节点，面包屑沿 `parent_id` 向上收集）——避免每次切换视图重复拉取数据；数据本体永远以 Rust 层为准。
- 布局：**左右双栏并列**，左「待处理」、右「已完成」，各占一半宽度并独立滚动，充分利用宽屏空间；两列均为常驻展开（不再默认折叠已完成）。
- 分组：
  - **待处理**（左）：pending 叶子，按树的深度优先顺序排列（同一任务线的叶子相邻）；
  - **已完成**（右）：done 叶子，按 `updated_at` 倒序。
- 每条目显示：checkbox + 内容 + 面包屑路径（`产品 A / 上线 / 买域名`，可视觉弱化）。
- 空态文案：「没有待处理的叶子节点，去树里看看吧」/「树还是空的，去创建第一个任务」/「还没有已完成的任务」。

### 3.3 与树形视图联动

- 点击平铺条目 → 切换到树形视图 → 自动展开其祖先路径 → 选中该节点并滚入视口、短暂高亮。
- 反向：树形视图中该节点如果被删除 / 变为非叶子，平铺视图刷新时自然消失（叶子定义由数据实时决定）。

### 3.4 为什么平铺视图只显示叶子？

中间节点是「任务的容器」，其进度由子节点聚合表达（`02-data-model.md` I2）；把容器和实事一起平铺会产生大量重复信息。叶子 = 可直接执行的原子事项，这正是「待办清单」的本体。

## 4. 节点操作全集

| 操作 | 快捷键（v0.1） | 行为 |
|---|---|---|
| 新建任务 | `N`（无焦点输入时）/ 顶栏「新建任务」 | 在根任务下新增 pending 子任务并进入编辑 |
| 创建子节点 | `Tab`（选中态）/ 节点 `+` 按钮 | 在当前节点下创建末位子节点并进入编辑；若父为 done 则父自动回退 pending |
| 创建兄弟节点 | `Enter`（选中态） | 在当前节点之后插入同级节点并进入编辑；根任务上按 Enter 等价于新建子任务 |
| 编辑内容 | `F2` / 双击 | 使用 Mind Elixir 内联编辑；`Enter` / `Tab` 提交，`Esc` 取消 |
| 切换状态 | 点击 checkbox / `S` | 按 M1/M2/M3 规则执行（含级联与传播）；Space 保留给画布平移 |
| 删除节点 | `Delete` / `Backspace` | 物理删除并级联删除子孙；根任务不可删除；静默删除 + toast 撤销（复用 Rust 历史） |
| 折叠 / 展开 | Mind Elixir 折叠角标 / `Ctrl+.` / `Ctrl+,` | 当前节点折叠 / 展开 |
| 上下移动焦点 | `↑` / `↓` | Mind Elixir 原生导航顺序 |
| 视图切换 | `Ctrl+1` / `Ctrl+2` | 树形 / 平铺 |

编辑态通用规则：编辑中 `Enter` / `Tab` 仅提交当前编辑（Mind Elixir 原生行为）；提交后再次按 `Tab` / `Enter` 创建子/兄弟节点；`Esc` 取消并还原。

## 5. 数据安全

- **自动保存**：所有 command 均为事务写，无「保存」按钮。
- **备份 = 导出**（v0.5）：应用不再生成自动/手动备份，备份与迁移统一通过「导出当前文档 / 目录 / 全部」完成，导入即整体还原。
- **损坏兜底**：SQLite 打开失败时不静默重置，直接报错并提示从导出文件恢复。

## 6. 侧边栏：文档与目录（v0.5）

- 层级：目录可无限嵌套，目录下可新建目录或文档；目录只存在于 `documents.json` 索引，文档数据仍是独立 SQLite 文件。
- 交互：**同一时刻只有一个选中项**——单击目录选中它（决定「+」新建的落点，顶部菜单会显示「在「X」下新建」），单击文档则选中并打开该文档，之前的目录选中自动清除；展开 / 折叠走左侧箭头；双击重命名。
- 视觉：同级目录与文档的图标垂直对齐（目录的箭头占一列固定宽度，文档用同宽占位补上）。
- 展开 / 折叠按目录记忆（`tree-todo.sidebarCollapsed`），新建子项时自动展开父目录。
- 右键菜单：
  - 目录：新建文档 / 新建子目录 / 导出 / 导入到此目录 / 移动到… / 重命名 / 删除目录；
  - 文档：导出 / 移动到… / 重命名 / 删除文档。
- 「移动到…」二级菜单列出所有目录 + 根目录；目录不能移进自己或自己的子孙（`CyclicMove`）。
- 删除目录：**整个目录（含子目录与其中文档）作为一个条目进入回收站**，恢复时目录结构与文档归属原样还原；若会删空全部文档则拒绝。
- 宽度可拖拽（180–420px），松手即写入 `tree-todo.sidebarWidth`，重启后保持。

## 7. 导入 / 导出入口（v0.5）

| 入口 | 范围 | 说明 |
|---|---|---|
| 系统菜单栏「File → 导出全部…」 | 全部 | 根层级的所有目录与文档，打包成一个文件（macOS 在屏幕顶部菜单栏，Windows / Linux 在窗口菜单） |
| 系统菜单栏「File → 导入…」 | — | 导入到根层级 |
| 顶栏「更多 → 导出」 | 当前文档 | 仅导出正在编辑的文档 |
| 侧边栏右键（文档） | 该文档 | 导出 |
| 侧边栏右键（目录） | 该目录 | 含子目录与其中所有文档；「导入到此目录」把文件还原到该目录下 |

> 全局导出 / 导入只在系统菜单栏提供，顶栏不再放「文件」按钮，避免两套入口并存。

格式与还原规则见 `02-data-model.md` §5。

## 8. IPC 数据流约定（决策 D6）

- command 清单（v0.5）：`get_tree`、`create_node`、`update_content`、`update_note`、`toggle_status`、`delete_node`、`move_node`、`set_collapsed`、`expand_nodes`、`collapse_all`、`undo`、`redo`；文档 / 目录：`list_documents`、`create_document`、`rename_document`、`delete_document`、`create_folder`、`rename_folder`、`delete_folder`、`switch_document`、`get_current_document`；导入导出：`export_document`、`export_folder`、`export_all`、`import_bundle`。
- `create_node` 额外返回 `newId`（前端创建后立即选中并进入编辑态）。
- 每个**变更类** command 返回**受影响子树的最新快照**（操作节点 + 级联子孙 + 被传播修改的祖先链），前端 store 合并后受控刷新。
- **撤销约定（v0.2）**：除视图类命令（`set_collapsed` / `expand_nodes` / `collapse_all`）外，所有变更类命令必须记录历史（快照式 before/after，上限 100 步）；`undo` / `redo` 返回可直接合并的 patch（无历史时为 `null`）。节点删除也已改为物理删除，撤销通过历史快照恢复。
- **文档回收站（v0.4）**：删除文档不物理删除 SQLite 文件，而是把 `docs/{id}.db*` 移入 `trash/` 并在 `documents.json` 的 `trash` 列表中记录；恢复/彻底删除/清空只作用于文档文件。
- **查询类** command（全量树 / 叶子列表）在启动与视图切换时调用；万级节点下全量树预计 ≤ 1MB JSON，首次加载后常驻内存，后续靠变更快照增量合并。
- 所有 command 返回统一信封：`Ok(T)` / `Err(AppError)`；`AppError` 带 i18n 就绪的错误码（如 `CyclicMove`、`NodeNotFound`）。
