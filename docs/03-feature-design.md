## 2. 树形（脑图）视图

### 2.1 布局

- **方向**：从左到右的水平树（根在左、子节点向右生长），符合「任务分解」的心智模型；多根纵向排列。
- **实现（决策 D4）**：`@xyflow/react`（react-flow）提供画布基础设施（pan / zoom / 视口 / 节点渲染容器），`d3-hierarchy` 的 `tree()` 布局计算各节点 `(x, y)` 坐标，连线用三次贝塞尔曲线（`getBezierPath`）。
- **重算时机**：任何结构变化（增删 / 折叠 / 移动）后重算布局，节点位置以 CSS transition 平滑过渡（时长 ≤ 200ms）。
- **尺寸**：节点宽度按内容自适应（有上限 min/max），高度统一；父子连线锚点在节点左右两侧中点。

### 2.2 节点视觉状态

| 状态 | 样式 |
|---|---|
| pending | 空心圆圈 checkbox + 正常文字 |
| done | 实心对勾 + 文字划线 + 整体降透明度；其下连线整条变灰（传达「这条支线已走完」） |
| 选中 / 焦点 | 描边高亮；焦点节点响应键盘操作 |
| 编辑中 | 节点就地变为输入框（contenteditable / textarea 自适应） |

### 2.3 画布交互

| 操作 | 交互 |
|---|---|
| 缩放 | 滚轮缩放（以指针为中心），Ctrl+滚轮 同义；10%–400% |
| 平移 | 空格 + 拖拽 / 触控板 / 中键拖拽 |
| 适应视图 | 快捷键（Shift+1）与工具栏按钮：缩放至整树可见 |
| 定位 | 双击空白处回中心；点击平铺视图条目跳转定位（见 §3.3） |

### 2.4 折叠 / 展开

- 节点在「有子节点」时显示折叠按钮（`−` / `+` 角标）。
- 折叠状态持久化在 `nodes.collapsed`（见 `02-data-model.md` §1.3）。
- 折叠节点上显示被隐藏的直接子节点数角标（如 `+3`），提示里面还有内容。

### 2.5 性能策略

- 只渲染**未折叠路径上**的节点（折叠是第一优化手段）；
- 开启 react-flow 的 `onlyRenderVisibleElements`（视口裁剪）；
- 目标：可见节点 ≤ 2000 时保持 60fps；5000 节点树（折叠后可见 ≤ 500）交互无感知延迟。

## 3. 平铺视图

### 3.1 定位

树形视图看**结构**，平铺视图看**存量**：把所有叶子节点拉平，集中显示「还有哪些事没做」「做完了哪些」。

### 3.2 设计

- 数据来源：Rust command `list_leaves()`，返回所有无子节点（叶子）的节点，附「层级路径面包屑」。
- 分组：
  - **待处理**（默认展开）：pending 叶子，按树的深度优先顺序排列（同一任务线的叶子相邻）；
  - **已完成**（默认折叠，可展开）：done 叶子，按 `updated_at` 倒序。
- 每条目显示：checkbox + 内容 + 面包屑路径（`产品 A / 上线 / 买域名`，可视觉弱化）。
- 空态文案：「没有待处理的叶子节点，去看看树吧」/「树还是空的，去创建第一个任务」。

### 3.3 与树形视图联动

- 点击平铺条目 → 切换到树形视图 → 自动展开其祖先路径 → 视口平移到该节点并短暂高亮。
- 反向：树形视图中该节点如果被删除 / 变为非叶子，平铺视图刷新时自然消失（叶子定义由数据实时决定）。

### 3.4 为什么平铺视图只显示叶子？

中间节点是「任务的容器」，其进度由子节点聚合表达（`02-data-model.md` I2）；把容器和实事一起平铺会产生大量重复信息。叶子 = 可直接执行的原子事项，这正是「待办清单」的本体。

## 4. 节点操作全集

| 操作 | 快捷键（v0.1） | 行为 |
|---|---|---|
| 创建根节点 | `N`（无焦点输入时）/ 工具栏按钮 | 画布尾部新增 pending 根节点并进入编辑 |
| 创建子节点 | `Tab`（选中态）/ 节点 `+` 按钮 | 在当前节点下创建末位子节点并进入编辑；若父为 done 则父自动回退 pending |
| 创建兄弟节点 | `Enter`（选中态） | 在当前节点之后插入同级节点并进入编辑；对根节点则为新建根 |
| 编辑内容 | `F2` / 双击 / 直接输入 | 就地编辑，`Enter` 提交，`Esc` 取消 |
| 切换状态 | `Space` / 点击 checkbox | 按 M1/M2/M3 规则执行（含级联与传播） |
| 删除节点 | `Delete` / `Backspace`（内容为空时） | 删除并级联删除子孙；**弹出轻量确认（展示子节点数）**，v0.2 接入撤销后改为「静默删除 + 可撤销」 |
| 折叠 / 展开 | `Ctrl+.` / `Ctrl+,` | 当前节点折叠 / 展开 |
| 上下移动焦点 | `↑` / `↓` | 深度优先顺序移动选中焦点 |
| 视图切换 | `Ctrl+1` / `Ctrl+2` | 树形 / 平铺 |

编辑态通用规则：编辑中 `Tab` / `Enter` 直接提交当前编辑并执行对应创建操作（连续录入的心流）；`Esc` 取消并还原。

## 5. 数据安全

- **自动保存**：所有 command 均为事务写，无「保存」按钮。
- **启动备份**：启动时若 `tree-todo.db.bak` 与当前文件校验一致则跳过；备份文件放同一数据目录，v0.1 只保留最近 1 份（v0.3 扩展为 3 份）。
- **损坏兜底**：启动时 SQLite 打开失败 → 引导用户从 `.bak` 恢复（复制回主文件），不静默重置。

## 6. IPC 数据流约定（决策 D6）

- 每个**变更类** command 返回**受影响子树的最新快照**（操作节点 + 其祖先链 + 受影响的兄弟集合），前端 store 合并后受控刷新。
- **查询类** command（全量树 / 叶子列表）在启动与视图切换时调用；万级节点下全量树预计 ≤ 1MB JSON，首次加载后常驻内存，后续靠变更快照增量合并。
- 所有 command 返回统一信封：`Ok(T)` / `Err(AppError)`；`AppError` 带 i18n 就绪的错误码（如 `CyclicMove`、`NodeNotFound`）。
